在 AstrBot 插件市场搜索 **astrbot_plugin_worldbook**，点击安装即可。

---

## 🤝 这是干嘛用的？

这是一个**关键词触发的提示词管理工具**。

简单来说：你可以预设一堆"人设卡"或"规则卡"（我们叫**条目**），当聊天中出现特定关键词时，插件就会自动把这些规则注入给 AI（默认附在本轮消息末尾，也可在配置面板切换为塞进 AI 的"大脑" system_prompt），让 AI 临时换个人格、换个语气，或者遵守特定规则。

**和普通的提示词有什么区别？**

- 普通提示词：说一次管一句
- 世界书：触发后持续生效一段时间，不用每次都提醒 AI

---


## 💡 实际应用场景

- **临时换风格**：让 AI 突然变严肃、变萌、变专业
- **剧情模式**：跑团时自动注入世界观设定
- **管理员模式**：触发后 AI 进入"教学模式"或"审核模式"
- **群聊彩蛋**：特定关键词触发隐藏人格

> **一句话总结**：这是一个**让 AI 动态切换提示词的规则引擎**。

---

## 🧠 怎么工作的？

1. 你发消息 → 插件检查是否命中某个规则
2. 命中了 → 把对应的人设卡塞进 AI 大脑
3. 接下来一段时间，AI 都会带着这个人设回复
4. 时间到了/次数用完了/你手动取消 → 恢复默认

## ⌨️ 命令大全

### 📌 只管当前聊天（普通用户也能用）

| 命令 | 干什么用的 |
|------|-----------|
| `条目状态` | 看看当前有哪些规则正在生效，还剩多久 |
| `清除条目` | 取消当前聊天的所有规则 |
| `清除条目 名称1 名称2` | 只取消指定的规则 |
| `启用条目 名称1 名称2` | 让某个规则在当前聊天可以触发 |
| `禁用条目 名称1 名称2` | 让某个规则在当前聊天不能触发 |

> 💡 这些命令**只影响当前聊天**，不会改全局设置

---

### 🧩 管理所有规则（需要管理员权限）

| 命令 | 干什么用的 |
|------|-----------|
| `查看条目` | 列出所有规则 |
| `查看条目 启用` | 只看已启用的 |
| `查看条目 禁用` | 只看已禁用的 |
| `查看条目 名称` | 看某个规则的详细信息 |
| `添加条目 名称 内容` | 快速新建一个规则 |
| `删除条目 名称1 名称2` | 删除规则 |
| `重命名条目 旧名称 新名称` | 重命名规则（WebUI 编辑弹窗中直接改名称也可） |
| `设置触发词 名称 规则1 规则2` | 设置触发这个规则的关键词（支持正则） |
| `设置优先级 名称 数字` | 设置优先级，数字越小越优先 |

### ⚙️ 规则生效的底层逻辑

1. **触发检查**：消息命中关键词 → 检查是否在适用范围内 → 检查是否处于触发冷却 → 抽概率判定
2. **注入排序**：同一请求内按**触发先后**排列，先激活的排在前面（重复触发会刷新到末尾）；`priority` 决定同一消息同时命中多时的候选顺序与存储/展示顺序
3. **注入位置**：每个条目可单独配置 `inject_position`（`default` 跟随全局 / `user_input` / `system_prompt`），无论注入到哪一部分，都统一追加到该部分**末尾**；`user_input` 模式用 `<世界书设定参考>` 标签包裹并注明非用户发言，优先走宿主的 `extra_user_content_parts` 通道发给模型但不落盘到会话历史（宿主过旧时自动回退为追加用户输入）；历史中残留的注入块会在每次请求前自动剔除
4. **数量限制**：超过 `max_inject_count` 的后触发规则会被丢弃

## 🖥️ WebUI 管理页（推荐）

插件自带一个网页管理页面（基于 AstrBot 官方 Plugin Pages 能力）：

- **打开方式**：AstrBot WebUI → 插件 → 世界书插件卡片 → 插件详情 → Pages（需 AstrBot **≥ v4.24.1**，旧版本无此入口）
- **能做什么**：
  - 按名称 / 触发词 / 生效范围 / 启用状态 / 注入位置**筛选**条目，逐条编辑全部参数，也可新建、删除条目（卡片上可直接启用/禁用）
  - **修改条目名称**：编辑弹窗中直接改名，保存时自动重命名（会话中的激活副本同步更新）
  - **定时配置**：开关式启用（不启用时不展开后续配置）+ 模式（每天 / 每周）+ 触发方式（时刻增删 / 全天 / 时间段，支持跨天）、星期勾选、起止日期选择、节假日过滤（全部 / 仅工作日 / 仅节假日与周末），**无需手写 cron 表达式**
  - 一键**预览未来执行时刻**（如「下一次执行日期：2026-10-01 08:00」）
  - 每个条目展示示范场景：「当检测到{关键词}时将注入到{注入位置}」「下一次执行日期{执行日期}」等可读话术
  - **导入 / 导出**：工具栏「⬇ 导出」把全部条目导出为 JSON 文件（浏览器直接下载，文件名形如 `worldbook_20260926_153000.json`）；「⬆ 导入」选择 JSON / YAML 文件导入，导入前弹窗选择**跳过同名**（保留现有配置）或**覆盖同名**（用文件内容替换），导入完成后提示新增 / 跳过 / 无效条目数量
  - 直接修改全局注入位置等配置
  - 界面采用**类水墨屏暗色配色**，低亮度低刺激，夜间使用友好

> 💡 聊天命令依然可用，WebUI 适合批量管理与精细化配置。
> 📄 导入支持本插件原生格式（含导出文件）与**酒馆 SillyTavern Lorebook 格式**（自动映射触发词、内容、概率、常驻等字段）。

### ⏰ 节假日 / 工作日说明

定时过滤依赖**中国法定节假日数据（含调休）**：内置 `chinese-calendar` 离线数据优先，超出其覆盖年份时自动调用 timor.tech 在线接口查询并缓存到插件数据目录；两者都不可用时按自然周（周一至周五=工作日）估算并在日志中提示。

## 📋 一个规则（条目）包含什么？

> ℹ️ 自 v2.6.0 起不再区分条目模板，所有条目统一使用同一套字段与默认值。旧版本数据（含 `template` / `cron` 字段）会在插件启动时自动检测并迁移清洗，无需手动处理。

| 字段名                 | 必填 | 说明（面向用户）                                               |
| ------------------- | -- | ------------------------------------------------------ |
| `name`（名称）          | ✅  | 条目的唯一标识，用于管理、查询和命令操作；可在 WebUI 或命令中重命名；当未设置关键词时，会自动作为默认触发词 |
| `content`（注入内容）     | ✅  | 条目真正生效时注入给模型的**规则 / 设定 / 状态背景**（不是一次性指令）               |
| `enabled`（启用）       | ❌  | 总开关。关闭后该条目**完全不参与任何激活判断**                              |
| `keywords`（触发词/正则）  | ❌  | 当消息包含这些关键词或匹配正则表达式时，条目才可能获得触发资格；留空则不通过消息内容触发（可仅靠定时触发） |
| `priority`（优先级）     | ❌  | 多个条目同时生效时的注入顺序，**数字越小越靠前、影响越强**                        |
| `probability`（触发几率） | ❌  | 在满足所有其他条件后，最终生效的概率（0~1），常用于随机事件                        |
| `cooldown`（触发冷却）    | ❌  | 单次激活后，在本会话的指定秒数内不会再次激活；`0` 表示不冷却                        |
| `duration`（生效时长）    | ❌  | 条目成功生效后可持续的时间（秒）；`0` 表示永久生效                            |
| `times`（生效次数）       | ❌  | 在一次生效周期内最多注入的次数；达到上限后即使仍在时长内也不再生效；`0` 表示不限             |
| `scope`（生效范围）       | ❌  | 限制哪些会话 / 群聊 / 用户的消息才可能触发该条目；填 `admin` 表示仅管理员可用；留空表示不限制 |
| `inject_position`（注入位置） | ❌ | `default` 跟随全局配置（默认）/ `user_input` 注入本轮用户消息末尾（缓存友好）/ `system_prompt` 注入系统提示词末尾 |
| `schedule`（定时触发）    | ❌  | 结构化定时配置：`mode`（none/daily/weekly）+ 触发方式（`times` 时刻列表 / `all_day` 全天 / `time_start`+`time_end` 时间段，支持跨天）+ `weekdays`（1=周一…7=周日）+ `start_date`/`end_date`（日期范围）+ `day_filter`（all/workday/holiday 节假日过滤）；「某一天全天」= 起止日期设为同一天 + 全天；推荐在 WebUI 管理页可视化编辑 |

## ✍️ 编写世界书

配置条目有三种方式：在 AstrBot 配置面板中直接编辑、在 WebUI 管理页可视化编辑（推荐），或用聊天命令快速增删改。

写好的世界书文件（JSON / YAML）可以在 WebUI 管理页用「⬆ 导入」加载；导出同理。

不会写怎么办？请参考内置世界书 `default_lorebook.yaml`（插件目录下），它同时是本插件条目 YAML 格式的完整范本。

内置世界书在配置的条目为空时自动加载。

### 通配符支持

你可以在规则内容里加"变量"，注入时会自动替换成实际值，例如：

```text
 {user_name} 是你的生死死党，
    关系核心为相爱相杀。
    彼此是对方最信任、最亲密的挚友，
    知根知底、不分彼此，
    会毫无保留地交心、撑腰，
    也会日常互损、拌嘴、拆台。
```

目前支持的变量还不多，后续会补充：

| 变量 | 会变成 |
|------|--------|
| `{user_id}` | 用户的 ID |
| `{user_name}` | 用户的名字 |
| `{time}` | 当前时间（时:分:秒） |

> ⚠️ 写错了的变量会原样保留，不会报错。目前支持的变量还不多，后续会加。
